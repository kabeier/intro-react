Speed and consistency vs control.

Different from the curriculum (until merged): Bootstrap 5 does not need jQuery; React Bootstrap never did.

What is React Bootstrap?

  • Bootstrap's components rewritten as React components
  • bootstrap = the CSS · react-bootstrap = the components
  • One import per component: import Card from 'react-bootstrap/Card'

You need both packages: components and their CSS.

Versions: react-bootstrap 2.10 (3.0 is still beta), bootstrap 5.3.

Why Bootstrap wins: cascade layers

RuleWhere it livesWins?
Tailwind .font-boldinside @layer utilitiesno
Bootstrap h1 { font-weight: 500 }no layeryes: unlayered beats every layer
Tailwind with importantlayer, !importantyes: layered !important beats unlayered

Import order does not fix it; important does.

This is why "just import Bootstrap first" (the curriculum's order) isn't enough with Tailwind v4.

Two libraries in one app: the rules

  • @import "tailwindcss" important; so utilities win clashes
  • One library per component: PokeCard is Bootstrap; everything else is Tailwind
  • A guard test (computed styles) tells you when a clash comes back

In real projects, pick one. Today we learn both.

Alternative: prefix(tw) renames Tailwind's classes; it avoids name clashes but not Reboot's element styles.

When should you use React Bootstrap?

Pick a component library when…Pick utilities when…
you need it working today (admin pages, prototypes)there is a design to match
you need modals, dropdowns, tooltips that just workyou want small CSS and full control
the team knows Bootstrapthe team knows Tailwind

Both are fine. Mixing them costs a guard test and a rule.

Ask: "Which one would you pick for the final project, and why?"
