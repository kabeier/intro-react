Rendering vs effects

Rendering

App() returns JSX. Must be pure: same state in, same JSX out. No requests, no timers, no touching the page.

Effects

Run after React has updated the page: requests, logging, timers, changing things outside React (document.body).

Draw in the component; talk to the outside world in an effect.

Say: "If it isn't drawing, and it isn't a reaction to a click, it's probably an effect."

Why the ignore flag?

TimeWithout ignoreWith ignore
effect run 1 starts a requestrequest Arequest A (ignore₁ = false)
cleanup (StrictMode, or the page leaves)—ignore₁ = true
effect run 2 starts a requestrequest Brequest B (ignore₂ = false)
A's answer arrivesused (maybe after B: stale data)thrown away

An answer for an effect that was cleaned up must not change state.

This is react.dev's pattern for requests in effects. Without it, a slow first answer can overwrite newer data (a race).

Different from the curriculum (until merged): it fetched with no cleanup.

When NOT to use an effect

SituationUse
Something happens because the user clickedthe click handler
A value you can compute from statecompute it while rendering (no state, no effect)
Keep something outside React in sync (body colour, title, a timer), or load datauseEffect

Effects are for the outside world.

The background colour could also be set in the click handler; we use an effect because it follows count wherever it changes.

Mental model

  • Render = pure: state in, JSX out
  • Effect = after render: sync with the outside world
  • Dependencies = the values the effect reads
  • Cleanup = undo, and ignore late answers
