The rule for state

Who needs it?Where it livesExample
one componentin that componentone card's shiny
several componentsin their closest common parent"shiny for all cards"; the Pokemon list

Keep state as low as you can; lift it only when it must be shared.

That is react.dev's rule ("lifting state up").

Who should own the form's text?

Curriculum: PokemonForm owns it

The form keeps pokemonName and calls the parent with the name on submit. The parent never sees the typing.

Ours: PokeSearch owns it

PokeForm only shows the box. PokeSearch keeps the text, so it can clear it after a search.

Both work. Ask: who else needs this value?

If nothing outside the form needs the text, the curriculum's version is simpler. We keep ours: the search clears the box.

Common state mistakes

MistakeWhat happensInstead
changing a prop inside the childnothing re-renders; React warns or crashescall a function from the parent
key={index} on a list that changesstate jumps to the wrong cardkey={pokemon.id}
shared state kept in a childsiblings can't see itlift it to the common parent
one card's state kept in the parentevery card changes togethermove it down into the card

Wrong place = wrong behaviour. The tests catch it.

Mental model

  • State lives as low as possible
  • Shared state lives in the closest common parent
  • Every copy of a component has its own state
  • Stable keys keep that state with the right item
