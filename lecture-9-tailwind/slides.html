The motivation behind Tailwind

Plain CSS (App.css)Tailwind
invent a class name: .card, .card-title…use ready names: rounded-xl, p-4
switch files to see the stylethe style is on the element
old rules pile up; nobody dares delete themdelete the element, its style goes too

A utility class does one thing, and its name says what.

The plan: Why Tailwind: use ready-made class names on the element instead of inventing your own.

Tailwind and React

  • Components are the reuse: style Button once, use it everywhere
  • Conditional classes: className={shiny ? 'ring-4 ring-yellow-400' : ''}
  • Write class names whole: Tailwind finds them by reading your files, so {`bg-${color}-500`} is never generated

Long class lists are fine; repeated ones become components.

The plan: How Tailwind works with React: components are the reuse, and class names must be written whole.

The whole-names rule surprises everyone once.
